Responsibilities of the Controller Layer

  • Request Handling: Accept HTTP requests (GET, POST, PUT, DELETE).
  • Validation: Validate input data (e.g., ensure required fields are present).
  • Business Logic: Process requests by interacting with the Model layer.
  • Response Generation: Return appropriate HTTP responses (e.g., JSON, HTML, or error messages).

Desing Of Controller Layer

This controller design organizes how the app handles requests for cricket data. Each table (Players, Teams, Matches, etc.) has its own controller with endpoints for common operations like adding, updating, deleting, and fetching data. For example:

  • Players: Add, update, or delete players; fetch all players or a specific one.

  • Teams: Manage teams similarly.

  • Matches: Add matches, fetch match details, or get players in a match.

  • Deliveries: Track ball-by-ball details for matches.

  • Dismissals: Record how batsmen get out.

  • DismissalFielders: Track fielders involved in dismissals.
